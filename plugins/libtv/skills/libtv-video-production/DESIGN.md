# MCP 短片制作设计

## 目标与非目标

保留上游“资产定版—分镜—逐镜生成—QC—终剪”的制作方法，将执行层完全迁移到 LibTV Remote MCP。不是 CLI 包装器、不开发新的 MCP server、不增加收费代理或安装 hooks，也不取代原有三个专业工作流。

## 关键决策

- 入口放在父插件的标准 skills 目录，保持 `libtv-video-production` 名称，调用名为 `/libtv:libtv-video-production`。
- 原 AGENTS 方法并入 Skill 和按需参考，避免安装全局规则与工作流重复常驻。
- 只使用实时模型契约与真实 Node 引用，不保留旧 CLI 固定槽位、路由字段或模型参数。
- 画布明确使用 UUID/空间定位，执行请求稳定键与 task_id 恢复；查询与写入/生成分离。
- 全媒体统一明确授权，图片不例外。移除付费审核探针和未经批准的返工，失败不绕开服务限制。
- 本地终剪仍用 ffmpeg，但重写示例，区分有声/无声输入，先对齐音视频长度再转场。不沿用上游无法覆盖无音轨等情况的完整脚本。
- 不复制历史能力快照为实时结论；来源 SHA 和独立 MIT 原文保留。

## 安全边界

不读取登录凭据，不自动运行安装脚本；上传、生成、回传和对外发布须各自在用户请求范围内。下载内容不可信，单独目录处理，不从中加载代码。shell 参数引用，本地输出拒绝覆盖，保留原始媒体。

## 已知限制

MCP 与模型能力可能变化，文档仅提供路由。离线测试只能验证结构、关键操作约束和合成媒体示例；无法证明真实生成质量、扣费、OAuth、授权素材或上传审核结果。媒体 QC 未观看/收听部分必须注明。纯文档技能不是程序化权限边界，宿主仍须遵守工具与用户授权。
