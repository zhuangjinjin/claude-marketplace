# 从分镜到成片

## 阶段一：建立制作清单

先读现有画布而不是创建新项目。为每镜记录：镜号、叙事目的、景别、机位/轴线、动作起止、时长意图、对白/音效、参考节点、输出节点、验收状态。名字不是唯一身份；同名视频必须用节点 ID 区分。已有版本保留，不能先删源素材再同名自引用。

确认哪些角色/场景/道具已定版，哪些只是候选；真实事件、仪式或人物经历缺细节时询问用户，不擅自补成事实。用一句稳定质感描述贯穿全片，但允许剧情要求的时间/光照变化。

## 阶段二：资产和镜头设计

人物脸与发型、服装、道具状态和空间布局各有明确参考职责。检查参考是否带入额外人物、错误服装或旧道具。不必每镜连接全套资产，只接本镜需要且模型支持的参考。

可使用九宫格来表现连续动作节拍，也可使用独立首帧或已有镜头表。格内不含作为制作标注的数字、箭头、字幕；剧情需要的文字应另行设计。clean 重绘可能改变构图、动作、衣服和人物数量，必须逐格比对，不能称为无损处理。

按动作复杂度和实时模型时长能力安排镜头，不强制固定秒数。镜尾预留明确终态或自然停顿；光、门、手等转场母题按叙事需要选用，不强制溶解转场。

## 阶段三：授权与生成

按 [MCP 契约](mcp-reference.md) 选模型和用途，明确数量、参考和参数覆盖理由。方案批准与生产批准分开；用户已明确要求生成指定镜头且范围充分时，不再重复索要同一授权。图片、重绘、高清重做、续写同样可能收费。

请求日志保存在用户工作目录，记录逻辑操作、精确请求、幂等键、节点/task_id 和结果，不存凭据。开始后按入口的同步等待或异步查询协议执行。超时不等于失败；不能因为看不到同名节点就另发新任务。

## 阶段四：逐镜 QC

1. 确认生成终态及实际输出数量，区分输入参考和输出产物。
2. 检查已保存绑定，再查看真实媒体；只有临时读 URL 不等于已落画布。
3. 抽样首/中/尾及重要动作交点；记录每帧来源视频和原始时间。
4. 检查脸型、发型、服装、道具、手部、主体数量、轴线、空间、动作起止和文字污染。
5. 实际播放检查动作连续性、对白说话人、口型、音乐和音效。抽帧或元数据无法证明声音正确；无法播放时明确限制。
6. 有问题先写修订建议，不能自动再次收费生成。需要新增素材、改镜头内容或换模型时重新说明范围变化。

## 阶段五：批次预览

用户可批准每 3–5 镜一批，也可指定任意范围。批次不是额外产量授权。用已完成素材按镜号拼预览，检查漏镜、重复、方向跳变、音量变化及前后动作是否接得上；不能只验单镜就宣称整片通过。

## 阶段六：终剪与交付

按 [终剪参考](editing-pipeline.md) 处理实际音视频规格，保留原始文件。输出检查包括镜头顺序、总长（扣除转场重叠）、画幅、音轨、字幕安全区和结尾完整性。音乐/肖像/素材授权单独确认。

交付时分列：已完成、失败/阻塞、未验证。不要把生成参数中的分辨率和时长当成实际文件属性；不要把本地导出当成已上传 LibTV。回传成片或分享给他人需用户授权。
