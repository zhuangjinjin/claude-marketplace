# LibTV 短片制作 · MCP 版

## Claude Code compatibility

通过当前插件已经授权的 LibTV Remote MCP 操作，不要求 LibTV CLI 或另一次 CLI 登录。工具名只作发现线索，实际参数服从当前工具 schema 与服务说明。按本文件位置解析同目录参考文档，不假设当前工作目录是插件缓存。创作文件、下载和剪辑产物放在用户选定的项目工作目录，不写插件安装目录。

LibTV 服务端 Agent / Skill 不等于 Claude 的 Agent / Skill。此工作流由当前助手直接编排，不默认委派服务端 Agent，不要求额外模板选择，也不依赖 Codex 内嵌浏览器。

## 先确定本次范围

- 识别用户是要只读盘点、写方案、生成某张图/某个镜头、检查已有视频，还是剪辑成片。只做请求阶段，不强制从头重做。
- “看看/计划/检查”不授权写画布、上传素材或付费生成；已有参考图、首帧和视频优先复用。不能为使用技能新建同名画布或重生成已有资产。
- 图片、视频、音频等收费操作都必须有明确授权；“生成一张”只生成一张，不加备选，不继承旧节点的大 count。批量授权明确镜头范围、数量和允许重试预算；预算未知就说明未知，不编价格。
- 执行前用 `doctor` 检查连接和执行准入；再用 `project_list`（需要时分页）与 `target_project` 精确定位画布 UUID 和空间。用户说的项目名与画布名可能不同，同名歧义先确认。
- 读取 [MCP 操作契约](references/mcp-reference.md)；只在生成阶段查询实时模型，不拿真实任务试参数。没有连接、工具或权限时说明阻塞，不改走旧 API 或本地凭据。

## 工作流

### 1. 盘点与定调

通过 `read_project` / `read_node` 记录现有角色、场景、道具、分镜、视频和参考连线，区分名称/提示词记录与已观看的画面。只有 URL 或任务完成状态不等于已经质检。

确认目标画幅、成片长度、风格、语言/对白、配乐、交付格式和本次允许的操作。保留用户已定版风格，不预设 2D、写实或国漫。形成固定质感描述和每镜清单：叙事目的、动作起止、参考节点、声音、衔接点、状态。

详细步骤见 [制作流程](references/production-workflow.md)。

### 2. 资产与分镜

复用用户认可的人物面部/全身、场景布局、关键道具与状态图。实际检查参考图，不单凭名称认定“同一个人物/同一把刀”。缺失项先提出补充方案，在获得生成或上传授权后处理。

九宫格只是可选分镜表达方式，不把九格强制解释为九个独立视频。已有首帧/分镜可直接使用。需要九宫格时：一格一个可辨动作节拍、统一人物/轴线/道具，图内不写编号、箭头或字幕；文字镜头表单独保存。清理标注也是新的生成操作，必须有授权，并逐格检查是否改坏剧情与外观。

使用 [提示词配方](references/prompt-recipes.md) 拆分“叙事参考 / 外观锚点 / 场景布局 / 道具状态”，不套固定图片槽位。

### 3. 每镜生成

1. 报告当前镜头方案、真实参考节点、数量、拟用模型与时长；用户已有明确授权且方案未超范围时直接执行，不重复索要同一批准。
2. `search_models` → `get_model`，按实时能力选多参考生成、单首帧动画、首尾帧插值、编辑或续写。非指定参数沿用 Web 默认；不要把旧版 720p/1080p 或模型名当契约。
3. 提示词使用 `{{Node <nodeId>}}`，替换成实际 ID，并通过引用参数接入素材；不手工计算 Image/Mixed 编号。带参考任务不能降级为无参考生成来绕过不可用入口。
4. 提交前保存精确请求与稳定幂等键；按入口等待或保存 task_id。未知结果使用原请求/原键恢复，已有 task_id 则查询原任务，不能重建同名节点。
5. 用 `read_node` / `inspect_media` 核对结果、数量及持久化，再看片检查。参考校验成功不是人物和动作一致性验收。

### 4. 质检与批次预览

检查开场/中段/结尾及动作交接点：人物脸型发型服装、左右手持物、角色数量、空间轴线、运动方向、台词归属、口型、时长、格线/文字残留和结束状态。抽帧能发现静态问题，但不能证明全段动作、声音或口型正确；无法播放/收听时明确未验证项。

发现问题先定位来源（参考图 / 提示词 / 参数 / 产物），记录问题及修订计划，不自动收费重生。不改变用户剧情或删除角色来“修好”镜头。按用户批准的批次推进；可建议每 3–5 镜先做预览，但不能因此多生成镜头。

### 5. 本地终剪与交付

按照 [终剪流程](references/editing-pipeline.md) 使用 `ffmpeg` / `ffprobe`，先检测依赖。保留原片，输出到新文件。统一画幅、帧率、时间基、音轨与色彩处理；转场重叠时间必须从总时长扣除，不把硬切擅自改成溶解。

最终交付包含成片或明确的本地路径、镜头顺序、素材/音乐授权说明、实际可核验的媒体参数、完成与未完成检查项。上传成片回 LibTV 是单独的外发操作，需在请求范围内；不默认上传或发布。

## 失败与安全边界

- `run=false` 可能写画布，不能当成只读检查。
- 服务拒绝/审核失败时按可见原因报告，不做付费短片探针或反复替换参考以绕过审核。
- 不读取或复制登录 token，不输出签名 URL；不自动安装远程脚本、不修改用户权限配置。
- 本地下载、ffmpeg 和文件路径处理见 [安全与环境](references/content-safety-and-env.md)。缺工具时停止受影响阶段，其他独立的规划工作可以完成。
- 故障恢复见 [问题速查](references/pitfalls.md)，执行依据见 [能力边界](references/capability-boundaries.md)。
